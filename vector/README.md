# Векторная СУБД галереи (Qdrant)

Здесь хранятся эмбеддинги и метаданные галереи, а также выполняется векторный поиск (этап анализа, ТЗ п.4). Сами кадры лежат в SeaweedFS (`../storage`), связь через `image_id`.

Выбран [Qdrant](https://github.com/qdrant/qdrant): Apache 2.0, написан на Rust (ТЗ п.6), одна бинарная сборка в Docker, работает без интернета, косинусная метрика и HNSW из коробки, фильтры и группировка по payload, квантизация для галереи порядка 10^6 объектов (ТЗ п.10).

## Запуск

```bash
docker compose up -d --build --wait     # из каталога vector/ (или из aquila/ вместе с остальными сервисами)
```

Готовность: `qdrant` в состоянии `healthy`, `qdrant-init` завершился с кодом 0 (коллекция и индексы созданы). Без `.env` стек стартует с dev-ключом из `docker-compose.yml`; для демо-хоста ключ задаётся отдельно (см. `.env.example`).

| Что | Значение по умолчанию |
|---|---|
| REST снаружи | `http://localhost:6333` (`QDRANT_BIND`, `QDRANT_HTTP_PORT`); веб-панель `/dashboard` |
| gRPC снаружи | `localhost:6334` (`QDRANT_GRPC_PORT`) |
| Адрес из сети compose | `http://qdrant:6333` (REST), `qdrant:6334` (gRPC), сеть `falcon-reid` |
| Ключ API | заголовок `api-key`, переменная `QDRANT_API_KEY` |
| Коллекция | `gallery`, 512 × float32, Cosine |
| Образ | `qdrant/qdrant:v1.19.1` (`QDRANT_VERSION`) |
| Данные | volume `qdrant-data` (переживает `down`, удаляется только `down -v`) |

Порты по умолчанию слушают только localhost. Открывая Qdrant наружу (`QDRANT_BIND=0.0.0.0`), обязательно меняйте ключ API. `/readyz` отвечает без ключа, всё остальное требует ключ.

## Модель данных

Одна точка = один размеченный автомобиль в кадре (ТЗ п.5: в кадре бывает несколько ТС).

| Поле | Тип | Смысл |
|---|---|---|
| id | UUID | `uuid5(image_id, x, y, w, h)`: повторная загрузка перезаписывает точку, а не создаёт дубль |
| vector | float32[512] | эмбеддинг; Qdrant нормирует его при записи, `score` равен косинусному сходству |
| `image_id` | keyword, индекс | ключ кадра в бакете SeaweedFS |
| `bbox` | [x, y, w, h] | рамка в пикселях исходного кадра |
| `vehicle_id` | keyword, индекс | идентичность ТС (у галереи известна, у запросов нет) |
| `split` | keyword, индекс | `gallery`, `train`, `val`, `test` или `user` (скрипт `load_gallery.py` принимает любую метку; backend пишет `user`, `val`, `train`, `test`, `gallery`) |
| `row` | int | номер строки в CSV: связывает точку со строкой `embeddings.npy` (ТЗ п.8); есть только у точек, загруженных скриптом |

`bbox` у точек, загруженных скриптом, список `[x, y, w, h]`, у точек, добавленных backend-ом, объект `{x, y, w, h}`; backend использует `bbox` из PostgreSQL, а не из payload. `id` считается по разному пространству имён uuid5 у скрипта (`6f0f8a3e-5a0e-4c53-9d0a-4f414c4b4c4f`) и у backend (`uuid.NAMESPACE_DNS`), см. `../docs/backend.md`, раздел 8, №3.

Размерность задаётся `EMBEDDING_DIM` (модель `JDNF_BNNECK_PROTO2` на DINOv3 ViT-L/16 даёт 512, `../docs/methods.md`, раздел 2). Если размерность изменилась, инициализация остановится с понятной ошибкой: коллекцию нужно пересоздать, а не менять на месте.

## Загрузка галереи

```bash
pip install -r scripts/requirements.txt
python scripts/load_gallery.py --csv ./dataset/train.csv --embeddings ./train_embeddings.npy --split gallery
```

CSV в формате ТЗ п.5 (`image_id, x, y, w, h, vehicle_id`), `.npy` строка к строке с ним. Скрипт проверяет совпадение числа строк и размерности и безопасен при повторном запуске. Адрес и ключ берутся из `QDRANT_URL`, `QDRANT_API_KEY`, `QDRANT_COLLECTION`. На Windows в `QDRANT_URL` используйте `127.0.0.1`, а не `localhost`: иначе каждый запрос получает задержку около 2 с на разрешении имени.

## Подключение из backend

Так backend обращается к Qdrant в коде (`backend/app/services/searcher.py`):

```python
from qdrant_client import QdrantClient

client = QdrantClient(url="http://qdrant:6333", api_key=QDRANT_API_KEY)   # url=, чтобы клиент не переключался на HTTPS при наличии ключа

# Поиск: top-N со score, БЕЗ score_threshold. Порог применяется на backend (accepted = score >= порог),
# так интерфейс показывает и кандидатов ниже порога, и то, насколько лучший из них не дотянул до него.
hits = client.query_points("gallery", query=embedding, limit=10, with_payload=True).points
```

Два варианта, которые описаны в документах, но **в backend не используются**:

```python
# Порог на стороне Qdrant: пустой список = отказ, кандидаты ниже порога теряются
client.query_points("gallery", query=embedding, limit=10, score_threshold=THRESHOLD, with_payload=True)

# Один кандидат на автомобиль (в галерее у одного ТС несколько снимков): группировка по vehicle_id
client.query_points_groups("gallery", query=embedding, group_by="vehicle_id", group_size=1, limit=10)
```

- Порог отказа хранится в PostgreSQL и меняется в интерфейсе (одно место для поиска, метрик и экспорта, см. `PRODUCT.md`). Для метрики Cosine большее значение означает большее сходство.
- Точный перебор (`search_params=models.SearchParams(exact=True)`) в backend **не используется** даже при оценке метрик; поиск везде идёт по HNSW.
- Дополнительно backend умеет query expansion: первый проход `max(N × 5, 50)` точек с векторами, среднее запроса и первых пяти векторов, повторный поиск (`rerank=true`).
- Изображение кандидата backend читает из S3 по ключу `images/<image_id>.jpg` (`../storage/README.md`); скрипт загрузки кадров кладёт кадры по ключу `<имя файла>`, схемы ключей расходятся (`../docs/backend.md`, раздел 8, №4).
- Кросс-камерное исключение из ТЗ п.9 в репозитории **не реализовано**: камера участникам не передаётся, в коллекции её нет; встроенная оценка метрик backend не исключает даже самого запроса (`../docs/methods.md`, раздел 5).

## Масштабирование (ТЗ п.10)

Развёрнутый разбор с графиками (задержка и память в зависимости от N, открытые бенчмарки HNSW) — [`../docs/scaling.md`](../docs/scaling.md); графики генерирует `scripts/plot_scaling.py`.

Для галереи около 10^6 объектов включите скалярную квантизацию: `QDRANT_QUANTIZATION=scalar` (и пересоздайте коллекцию). Векторы int8 остаются в RAM, исходные float32 на диске используются для рескоринга.

| Режим, 10^6 × 512 | Векторы в RAM | На диске |
|---|---|---|
| `none` (float32) | около 2,0 ГБ | около 2,0 ГБ |
| `scalar` (int8 + рескоринг) | около 0,5 ГБ | около 2,5 ГБ |

Плюс граф HNSW (порядка 130 МБ при `m=16`) и payload. Цифры расчётные, замерьте на стенде.

Бенчмарк HNSW против точного перебора на синтетической галерее:

```bash
python scripts/benchmark_ann.py --n 1000000 --quantization scalar --url http://127.0.0.1:6333
```

Выводит recall@K, задержки p50/p95, пропускную способность, время загрузки и построения индекса. Данные синтетические (по 5 снимков на «автомобиль», шум вокруг центра): это проверка индекса, а не качества модели ReID, и в презентации так и надо подписывать. Контрольный прогон разработчика на 200 000 векторов, Docker Desktop на ноутбуке: recall@5 = 1.0, задержка HNSW p50 15 мс против 31 мс точного перебора (в задержку входит накладная на JSON и Python-клиент); прогон на 10^6 выполняется на стенде.

## Обслуживание

```bash
docker compose logs qdrant                       # логи
docker compose run --rm qdrant-init              # повторная инициализация (безопасна)
docker compose down -v                           # ВНИМАНИЕ: удалит все эмбеддинги галереи
```

Резервная копия: снапшот коллекции.

```bash
curl -X POST -H "api-key: $QDRANT_API_KEY" http://localhost:6333/collections/gallery/snapshots
# файл появится в volume qdrant-data (/qdrant/storage/snapshots)
```

Обновление версии: поменять `QDRANT_VERSION` в `.env` и выполнить `docker compose up -d --wait`. Qdrant рекомендует обновляться по одной минорной версии за раз; перед обновлением на демо-хосте сделайте снапшот.

## Запуск отдельно от остальных

Имя проекта compose у всех частей и корня одно (`falcon-reid`): общая сеть `falcon-reid` и тома `falcon-reid_<ключ>` одинаковы при запуске из корня и из этого каталога. Если соседние сервисы уже работают, при запуске отсюда Compose предупредит про orphan-контейнеры: это нормально, **не используйте `--remove-orphans`** (он остановит соседей); предупреждение убирает `COMPOSE_IGNORE_ORPHANS=true`.

## Ограничения

- Один узел без репликации: этого достаточно для демо и галереи порядка 10^6. Кластер и шардирование Qdrant поддерживает, но в поставку не входят.
- Ключи только из латиницы и цифр.
- Смена размерности эмбеддинга или режима квантизации требует пересоздания коллекции и повторной загрузки.
