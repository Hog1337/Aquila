# Датасеты

## Использованные датасеты

### Falcon ReID (основной)

- **Источник:** предоставлен организаторами хакатона
- **Объём:** 9 556 изображений, 1 541 ТС, 96 камер
- **Формат:** плоский каталог JPEG (1920×1080) + CSV с колонками `image_id, x, y, w, h, vehicle_id, camera_id`
- **Сплит:** разрезается на train_sub (75% машин) и val (25% машин)

### DN-ReID (Day/Night ReID)

- **Источник:** [GitHub](https://github.com/zhangchaobin0928/DN-ReID), CC BY-NC
- **Объём:** ~106 000 изображений, 1 574 ID
- **Использование:** совместное обучение (joint training) с Falcon для увеличения разнообразия условий (день/ночь)

### VeRI-Wild (Large-scale Vehicle ReID)

- **Источник:** [GitHub](https://github.com/PKU-IMRE/VERI-Wild), CC BY-NC
- **Объём:** ~277 000 изображений, 30 671 ID
- **Использование:** ключевой внешний датасет, давший наибольший прирост mAP (+0.069)

## Генерация валидационного сплита

**Скрипт:** [`training/split.py`](../training/split.py)

Сплит создаётся **строго по машинам (vehicle_id)**, не по кадрам, чтобы исключить
data leakage. Использован SEED=42 для детерминированности.

### Принципы

1. **Разрезка по identity:** все кадры одной машины — только на одной стороне (train_sub ИЛИ val)
2. **md5-дубли:** если один и тот же полный кадр содержит две разные машины (11 таких пар в датасете), обе машины попадают на одну сторону сплита
3. **25% машин → val:** 1 156 машин в train_sub, 385 машин в val
4. **Внутри val — paired (80%) и orphan (20%):**
   - **Paired** (341 машина): камеры каждой машины разбиваются на query-сторону и gallery-сторону так, что каждый val_query имеет ≥1 кросс-камерный позитив
   - **Orphan** (44 машины): все кадры только в val_query, в val_gallery их нет — имитация ~20% open-set запросов скрытого теста

### Результат нарезки

| Сплит | Изображений | Машин |
|-------|:-----------:|:-----:|
| `train_sub` | 7 176 | 1 156 |
| `val_query` | 1 261 | 385 |
| `val_gallery` | 1 119 | 341 |
| — в т.ч. paired query | 995 | 341 |
| — в т.ч. orphan query | 266 | 44 |

## Чистка данных

**Скрипт:** [`training/clean_dataset.py`](../training/clean_dataset.py)

### Мотивация
В процессе разметки датасета были допущены ошибки: неправильные BBox, размытые/закрытые
объекты, несоответствие vehicle_id. Эти кадры ухудшали обучение.

### Метод
Интерактивный веб-инструмент на Flask + V2-эмбеддинги (`JDNFV_SUPCON_PROTO_R32_best_ema_fp16.pt`):
- Для каждой машины показываются все её снимки
- Сходство между снимками рассчитывается через V2-модель
- Снимки с аномально низким средним сходством подсвечиваются
- Оператор отмечает «мусорные» кадры, результат записывается в `cleaning_results.csv`

### Результат

| Сплит | Исходно | После чистки | Удалено |
|-------|:-------:|:------------:|:-------:|
| train_sub | 7 176 | 7 033 | 143 |
| val_gallery | 1 119 | 1 080 | 39 |
| val_query | 1 261 | 1 241 | 20 |
| **Всего** | **9 556** | **9 354** | **202** |

## YOLO-сегментация (carseg)

Для этапа masked fine-tune (Этап 5) используется маскирование чужих машин в кадре.

### Модель сегментации
- **Архитектура:** YOLO11s-seg (или YOLO26n-seg на ранних этапах)
- **Датасет:** `stage2_real_v2` (20 классов частей автомобиля → union → car)
- **Подготовка:** [`training/baseline/make_car_dataset.py`](../training/baseline/make_car_dataset.py)
  — объединение 20 масок частей в одну маску «car» через dilation + внешний контур
- **Тренировка:** YOLO-seg, 1 класс (car), imgsz=640, 30 эпох
- **Результат:** Mask mAP50=0.955, mAP50-95=0.808, inference ~1.2ms/изобр.

### Инференс
YOLO загружается в inference-сервисе (`inference/app/main.py`) и применяется
к каждому кадру перед вычислением эмбеддинга: чужие машины заливаются фоном,
целевой кроп маскируется так, что остаётся только нужный автомобиль.
