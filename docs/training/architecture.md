# Архитектура модели

## Общая схема

```
вход: кроп 320×320×3 (ImageNet norm)
        │
        ▼
DINOv3 ViT-L/16 (заморожен)
  ├── LoRA (r=32, α=64) на q_proj, k_proj, v_proj, o_proj всех 24 слоёв
  └── Blocks 14–23 (разморожены, дифференцированный LR)
        │
        ▼
  hidden_states со слоёв [0, 4, 8, 12, 16, 20]  ← 6 тензоров × 1024
        │
        ▼
HeadBNNeck
  ├── 6 × LayerNorm
  ├── 6 × query-вектор → attention pool (softmax over patches)
  ├── concat → Linear(6144 → 2048)
  ├── BatchNorm1d(2048)
  └── L2-normalization
        │
        ▼
  эмбеддинг 2048 × float32 (L2-нормированный)
```

## Backbone: DINOv3 ViT-L/16

| Параметр | Значение |
|----------|----------|
| Модель | `facebook/dinov3-large` (HuggingFace) |
| Шаг патча | 16×16 |
| Число слоёв | 24 |
| Размерность токенов | 1024 |
| Голов внимания | 16 |
| Register tokens | 4 (DINOv3) |
| Вход | 320×320 (resize + нормировка ImageNet: mean=[0.485,0.456,0.406], std=[0.229,0.224,0.225]) |

Backbone загружается из предобученных весов Meta и **заморожен** (градиенты не считаются).
Адаптация происходит через LoRA и разморозку верхних блоков.

## LoRA (Low-Rank Adaptation)

| Параметр | Этапы 1–3 | Этапы 4–5 |
|----------|:----------:|:----------:|
| Ранг (r) | 16 | 32 |
| Alpha | 32 | 64 |
| Цели | `q_proj, k_proj, v_proj, o_proj` | те же |
| Модулей | 24×4 = 96 | 96 |

Инициализация: `kaiming_uniform` для A, `zeros` для B.
Прямой проход: `y = Wx + (x @ A^T @ B^T) · α/r`.

## Размороженные блоки

| Этап | Блоки | LR | Количество |
|------|-------|:---:|:----------:|
| 1–3 | 16–23 | 2.5e-6…2e-5 | 8 |
| 4–5 | 14–23 | 5e-6…2e-5 | 10 |

LR дифференцирован: ранние блоки (14–17) — меньше, поздние (21–23) — больше.

## HeadBNNeck (Multi-Query Attention Pooling)

Голова эволюционировала через несколько версий (детали — [`stages.md`](stages.md)):

### Финальная версия (Этап 4–5)

| Параметр | Значение |
|----------|----------|
| Слои для attention pool | 0, 4, 8, 12, 16, 20 (6 слоёв) |
| Query-векторов | 6 (один на слой, обучаемый) |
| LayerNorm | **Нет** (была в V1) |
| Внимание | Softmax над патчами для каждого query |
| Concat | 6 × 1024 = 6144 |
| Проекция | Linear(6144 → 2048) |
| Нормализация | BatchNorm1d(2048) → L2 |
| Классификаторы | 3 отдельных Linear(2048 → n_cls): Falcon, DN-ReID, VeRI-Wild |

### Принцип работы HeadBNNeck

Для каждого из 6 выбранных слоёв ViT:
1. Токены проходят через **LayerNorm** (в V1) или используются как есть (в V2)
2. Нормируются (L2) для стабильности внимания
3. Вычисляется attention: `w = softmax(tokens @ query / √d)`
4. Pooling: `pooled = sum(tokens * w, dim=1)`
5. Все 6 pooled-векторов конкатенируются → линейная проекция → BatchNorm → L2

**BNNeck:** BatchNorm1d стоит перед CE-классификатором. Это стандартный приём
из метрического обучения: BatchNorm «ломает» метрическую структуру эмбеддинга
для CE, заставляя классификатор работать в другом масштабе, а эмбеддинг
(до BN) сохраняет метрические свойства для SupCon и ProtoCon.

## Функции потерь

### Cross-Entropy Loss (основная)

```
L_CE = CrossEntropy(y, softmax(bn(embedding)))
```

- Label smoothing = 0.1
- Считается через BatchNorm (BNNeck)
- Отдельный классификатор для каждого датасета

### Supervised Contrastive Loss (SupCon)

```
L_SC = Σ_i -1/|P(i)| · Σ_{p∈P(i)} log( exp(e_i·e_p/T) / Σ_{a∈A(i)} exp(e_i·e_a/T) )
```

- λ = 0.3, T = 0.07
- Считается на **сырых** эмбеддингах (до BN)
- P(i) — все позитивы (тот же класс), A(i) — все остальные (включая сам anchor)

### Prototype Contrastive Loss (ProtoCon)

```
L_PC = CrossEntropy([pos_sim/T, neg_sim_1/T, ..., neg_sim_C/T], 0)
```

- λ = 0.15, T = 0.07
- Momentum prototype bank (momentum = 0.99)
- Каждый класс имеет прототип, обновляемый экспоненциально
- Anchor сравнивается со своим прототипом (позитив) и всеми чужими (негатив)

### Итоговая функция потерь

```
L = L_CE + 0.3·L_SC + 0.15·L_PC
```

## EMA (Exponential Moving Average)

- Decay = 0.999
- Обновляется после каждого шага: `ema = 0.999·ema + 0.001·param`
- На валидации и для финального чекпоинта используются EMA-веса
- Даёт прирост ~0.032 mAP

## Precision

Обучение в **bfloat16** (autocast). BF16 численно стабилен для DINOv3
(в отличие от fp16, которое даёт NaN). На GPU без поддержки bf16
(Compute Capability < 8.0) используется fp32.
